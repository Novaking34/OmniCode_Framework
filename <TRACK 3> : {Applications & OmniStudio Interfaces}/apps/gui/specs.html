The OmniCode Programming Language

An ontological, dual-readable programming language engineered by CreativeWorkzStudio LLC from first principles. Operates with bare-metal low-level precision while natively expressing balanced-ternary quad-state state machines, causal laws, and ethical invariants.

🏛️

The 4-Block Architecture

Every valid OmniCode unit must be structured into four sequential compilation blocks:

  1. Block 1: Metadata Block (Manifest) — Declares ontological identity, covenant anchor, and boundary classifications.
  2. Block 2: Opening Block (Opening { ... }) — Import libraries, assert immutable preconditions, and establish initial state vectors.
  3. Block 3: Body Block (Body [ ... ]) — Execute causal logic, balanced ternary rolls, and iterative computations.
  4. Block 4: Closing Block (Closing { ... }) — Verify post-conditions, reconcile invariants, and permanently seal transaction state.
⚖️

Balanced Ternary Quad-State Logic

Unlike binary logic (0 or 1), OmniCode operates on Balanced Radix-3 with a terminal Null state (T4):

  • +1 (Proceed): Affirmative forward vector (-->). Commits state mutations and advances the Turing reel.
  • 0 (Await): Standby, pass-through equilibrium, or asynchronous yield.
  • -1 (Rollback): Negation and boundary breach. Automatically unwinds retroactive vectors (<--).
  • NULL (Halt): Absorbing bottom type (⊥). Traps unrecoverable faults and terminates process.
🛡️

The 6 Boundary Types

  • < Invariant > — Absolute unalterable boundary. Immutable across all scopes.
  • < Finite > — Strictly bounded range, buffer capacity, or count.
  • < Indefinite > — Elastic state awaiting runtime determination.
  • < Continuous > — Streaming uninterrupted sequence or real-time feed.
  • < Absorb > — Trap boundary that swallows violations into safe fallbacks.
  • < Oscillate > — Alternating dual-phase harmonic boundary.
